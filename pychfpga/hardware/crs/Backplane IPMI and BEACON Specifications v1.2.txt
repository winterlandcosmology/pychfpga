Changelog
---------
V1.0
	1. Initial proposal by JFC

V1.1
	1. Moved crate information into the Product Information Area
	2. Removed the sub-backplane serial numbers. The rationale is that the
	   4SBP sub-backplane configuration is fixed and future backplanes will be
	   single-board and not have the concept of a sub-backplane. In the event of a
	   4SBP slot harware failure that needs to be tracked down, the backplane serial
	   number in combination with the 1-16 serial number modulo 4 is sufficient.
	3. Shift in nomenclature: the "Crate" is the unit or "Product" that t0 sells.
	   The "Chassis" is just one component of the crate that acts as a container for
	   the other components. The principle components of the crate are the
	   backplane(s) and the chassis. Other parts include the power supply, network
	   switch, etc. Replacing any of these components may warrant incrementing the
	   "Crate Revision" number or assigning the crate a new "Crate Model" entirely.
	   Either situation has been accounted for.
	4. The Model Number (Crate Model) and Product Name are TBD.

v1.2
	1. Remove Backplane info from beacon fields
	2. Corrected manufacturer name to "t0.technology"
	3. Documented transitional dual-firmware EEPROM encoding so one
	   image works with current U-Boot/TCPipe and v1.2 U-Boot


Backplane EEPROM IPMI FRU layout
---------------------------------
Common header (8 bytes)
  Offsets in the header point to areas in 8-byte units. Only the board,
  chassis, and Product areas are decoded for CRS backplanes.

Chassis Information Area  - identifies the *chassis*
  Standard IPMI field order (after a 3-byte prologue: version, length,
  chassis type):
    Field       IPMI name        Beacon field       Example value
    ---------   ---------------  -----------------  ----------------------------
    (prologue)  Chassis Type                        23d/17h (Rack Mount Chassis)
    1           Part Number                         (Vector Part Number)
    2           Serial Number                       71373 (Vector Serial Number)
    3           Custom field 1   Crate slot         15
                "slot=15"

Board Information Area - identifies the *backplane segment*
  Standard IPMI field order (type/length ASCII strings after a 6-byte prologue):
    Field       IPMI name        Beacon field            Example value
    ----------  ---------------  ----------------------  -----------------------
    (prologue)  Mfg. Date/Time                           F64E4C
    1           Manufacturer     Backplane Manufacturer  t0.technology
    2           Product Name                             4-slot backplane
    3           Serial Number    Backplane Serial        027
    4           Part Number      Backplane Model         4SBP
    5           FRU File ID                              (optional; often empty)
    6           Custom field 1   Backplane Revision      2
                "revision=2"

Product Information Area - identifies the *crate*
  Standard IPMI field order (after a 3-byte prologue: version, length,
  language code):
    Field      IPMI name        Beacon field        Example value
    ---------  ---------------  ------------------  -------------------------
    1          Manufacturer     Crate Manufacturer  t0.technology
    2          Product Name                         CRS Crate
    3          Model Number     Crate Model         CCR
    4          Product Version  Crate Revision      1
    5          Serial Number    Crate Serial        123
    6          Asset Tag                            (blank)
    7          FRU File ID                          (optional; often empty)

Transitional dual-firmware encoding
-----------------------------------
Current U-Boot 0.1 the Product area and treat chassis Part
Number / Serial Number as crate model. Until the next compliant uboot is out, we store the information like this:


  Board area     v1.2 backplane fields (compatible with all firmwares)
  Product area   v1.2 crate fields (ignored by uboot 0.1))
  Chassis area   Crate Model/Serial in Part Number/Serial number instead of Vector Model/serial.  
                 custom "slot=N" as field 1 (compatible with all firmwares)

With this format: uboot 0.1 will properly read crate and backplane serial numbers. Crate Manufacturer/model/revision and Backplane manufacturer/model/revision are not published). 
The next uboot will also have the correct and complete Crate/Backplane info, but the Vector chassis Model/serial wisll show duplicate crate information. That information is not announced in the beacon so it has little impact.
Backplane EEPROMs will have to be rewritten to get full Chassis information in the new uboot.

transitional format is obtained by programming  the backplane eeprom with:

    mb.set_backplane_eeprom(..., crate_in_chassis=True)
    )

Discovery beacon fields
----------------------

ASCII string consisting of name=value fields each separated by a linefeed character (ASCII code 10 or 0x0A):

Manufacturer: t0.technology
Product: crs
Revision: 5
Serial: 0216
Bootloader: u-boot  *See Note 1
Bootloader Version: 0.1   *See Note 2
Crate Manufacturer: t0.technology
Crate Model: CCR
Crate Serial: 011
Crate Revision: 1
Crate Slot: 15

Note 1: Corresponds to the firmware that is currently runnning on the ARM:
		"u-boot" for stock bootloader. 
		"tcpipe" for chfpga ARM firmware  
Note 2: Use git tag, or something that actually changes with the version

t0 Hardware:
------------
Motherboards
	Manufacturer: t0.technology
    Model: CRS
    Serial: 4 digits number
    Revision: <number>[<letter>]
Backplanes
	Manufacturer: t0.technology
    Model: 4SBP
    Serial: 3 digits number
    Revision: <number>[<letter>]
Crates
	Manufacturer: t0.technology
    Model: CCR
    Serial: 3 digits number
    Revision: <number>[<letter>]
