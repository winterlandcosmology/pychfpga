Data capture

The firmware can periodically send snapshots of the raw ADC samples or of the channelized data to the host over the 1G control link. This page assumes an initialized array ca (see Interactive operation) and a host configured for jumbo frames (see Networking).

Start the capture

await ca.start_data_capture_async(source="funcgen", period=1)

source selects what is captured:

  • "funcgen" (or 0): data after the function generator, i.e. ADC samples or an injected waveform

  • "scaler" (or 1): channelized data at the scaler output

Other arguments are passed to each board’s start_data_capture(): period (seconds between bursts), channels, data_type, mode (UCAP capture mode on RFSoC platforms) and send_delay. send_delay_per_slot staggers the boards in a crate so their bursts do not collide in the switch.

Read the frames

r = await ca.get_data_receiver_async()
ts, data, counts = r.read_raw_frames(ncap=4, flush=True)

read_raw_frames() returns timestamps, data and per-frame counts as NumPy arrays. With the default chan_first=True, data has shape (channels, bursts, samples).

Stop the capture

ca.ib.stop_data_capture()

For continuous capture and storage to HDF5, run the raw_acq server instead (see Server operation).
