class pychfpga.fpga_firmware.chfpga.chfpga_array_methods.chFPGAArrayMethods(fpga_array)

Bases: ArrayMethods

Array-wide methods for chFPGA firmware arrays.

FPGAArray instantiates this provider once the array is hardware-mapped and every motherboard shares the chFPGA firmware. Methods operate on self.ib / self.ic (the array motherboard and crate collections).

array_init_async() is the firmware-level init (channelizers, backplane, sync, operational mode). FPGA bitstream programming and MMI open are owned by FPGAArray, not this class.

Initialize chFPGA firmware after FPGAArray has programmed and opened the FPGAs.

This is firmware-level init (init >= 3): channelizers / CT engines, backplane, sync method, then operational mode (which itself ends with an array sync_async()). Bitstream programming, MMI open, and the program/open retry loop belong to FPGAArray.

If the array has no motherboards, this returns immediately.

Parameters:

  • mode (str) – Operational mode to apply at init >= 3. Required when init >= 3. See set_operational_mode_async() for platform-specific names (shuffle8, corr16, …). Stored as the default for later mode changes.

  • bitfile – Accepted for FPGAArray kwargs compatibility. Unused here; FPGAArray pops it before calling this method.

  • prog – Same as bitfile.

  • if_ip – Used by FPGAArray while opening MMI, not here.

  • fpga_ip_addr_fn – Same as if_ip.

  • udp_retries – Popped by FPGAArray before calling this method.

  • init (int or None) – Firmware init level. None becomes 3 if mode is set, else 0. Values below 3 skip firmware init (FPGAArray may already have programmed and opened the FPGAs). Values of 3 or more run init_fpga on every board, crate init(), then sync method and operational mode.

  • sync_method – Forwarded to set_sync_method_async(). If None at init >= 3, inferred as 'irig-b' when every board is in a crate, or 'local' when none are. A mixed crate/no-crate array logs a warning and leaves the method unset unless sync_source is also given.

  • sync_source – Forwarded to set_sync_method_async().

  • sync_master – Forwarded to set_sync_method_async().

  • sync_master_source – Forwarded to set_sync_method_async().

  • sync_master_output – Forwarded to set_sync_method_async().

  • max_sync_time_difference (float) – Maximum allowed Frame-0 IRIG spread in nanoseconds, stored for later sync_async() checks. Default 100 ns.

  • adc_mode (int) – ADC chip mode passed to each board’s init_fpga_async. Default 0 (normal data).

  • adc_bandwidth (int) – ADC analog bandwidth setting passed to init_fpga_async. Default 2.

  • frames_per_packet – Forwarded to set_operational_mode_async() at init >= 3.

  • chan8_channel_map – Forwarded to set_operational_mode_async() at init >= 3.

  • tx_power – Forwarded to set_operational_mode_async().

  • integration_period – Forwarded to set_operational_mode_async().

  • autocorr_only – Forwarded to set_operational_mode_async().

  • corner_turn_bad_links – Forwarded to set_operational_mode_async().

  • corner_turn_bin_priority – Forwarded to set_operational_mode_async().

  • corner_turn_remap_level – Forwarded to set_operational_mode_async().

  • sampling_frequency (float) – ADC sampling frequency in Hz, passed to init_fpga_async. None uses the platform/mode default.

  • **kwargs – Extra arguments forwarded to each board’s init_fpga_async (firmware init_async), e.g. processing_frequency, reference_frequency, data_width.

Returns:

None

Notes

  • get_ber() before shuffle/mode init will lead to errors (see set_operational_mode_async()).

  • All boards must have the same corner-turn engine type (or none); that is checked when the operational mode is applied.

get_raw_data_config()

Build (or reuse) the array-wide raw-capture config State.

Aggregates every board’s firmware config. The result is cached and returned unchanged until any board’s fpga.config has changed (has_changed / ack with context ('get_raw_data_config', self)). Static fields (sample size, frame length, …) are filled only on first build and must be common across the array.

All boards must use the same capture engine (UCAP or PROBER). Stream IDs across every active channel of every board must be unique or this raises ValueError (the host demuxes bursts by stream ID).

Returns:

State – Array-wide raw config, including source, channels, stream_ids, frames_per_burst, subframes_per_frame, target_mode, fft_bin_map, and capture_format[0/1] (funcgen vs scaler).

Raises:

  • RuntimeError – No boards in the array.

  • ValueError – Mixed/unknown capture engine, or duplicate stream IDs.

async set_gains_async(gains, bank=-1, when='now', gain_timestamps=None)

Set on-FPGA post-FFT digital gains for the given boards/channels.

Channel-keyed maps are regrouped with group_gains_per_board_id(). Gains are written with when=None on each board (no per-board bank switch). If this method’s when is not None, one array switch_gains_async() then activates the bank.

Parameters:

  • gains (dict) –

    Either:

    • {board_id: {chan: (glin, glog), ...}, ...}

    • {chan_id: (glin, glog), ...}

    where board_id is (crate, slot), chan_id is (crate, slot, channel), glin is 1024 complex linear gains, and glog is the post-scaler (gain 2**glog).

  • bank (int) – Bank to write. -1 or None writes the inactive bank (which can later be activated with switch_gains_async()).

  • when (int, str or None) –

    When to make the new table active:

    • 'now' or a negative integer: activate immediately.

    • None: write the bank but do not switch.

    • a non-negative integer: activate at that frame number.

  • gain_timestamps (dict or float or None) – Unix timestamps with the same key layout as gains, or a single timestamp applied to every channel. None means “now” on each board.

Returns:

None

  • board – Target board: serial string (with leading zeros), motherboard object, or (crate, slot) id as accepted by get_iceboard(). Falsy (None, '') skips setup and returns immediately.

  • enable (bool) – If True, enable PWM and route it to output.

  • offset (int) – Frames to wait after Frame 0 before the first pulse.

  • high_time (int) – High time of the PWM waveform, in frames. Default 8388608.

  • period (int) – PWM period in frames. Default 16777216 (so default duty cycle is 50%).

  • local_sync (bool) – If True, issue a local software sync on the target board after programming PWM.

  • output (str) – User output that drives the noise-injection hardware (set_user_output_source). Default 'bp_sma'.

async set_operational_mode_async(mode, frames_per_packet=1, send_flags=True, chan8_channel_map=[0, 1, 2, 3, 4, 5, 6, 7], tx_power=None, integration_period=16384, autocorr_only=False, corner_turn_bad_links=None, corner_turn_bin_priority=None, corner_turn_remap_level=0)

Set the operational mode of the array.

Configures the corner-turn engine on every board, optionally starts firmware correlators, then runs a full array sync_async().

Prerequisites:

  • FPGAs are programmed and opened, and array_init_async() (or equivalent init_fpga) has run so channelizers and CT engines exist.

  • Every board must have the same CT engine class (BCT or UCT).

  • Crate boards must use the backplane clock (check_clock_source() raises otherwise).

  • Do not call get_ber() before this; it leaves shuffle links in a state that breaks mode init.

Parameters:

  • mode (str) –

    Operational mode. Platform-specific:

    IceBoard:

    • 'chan4': Corner-turn engine is bypassed and raw 4-bit data from 4 channelizers is sent directly to the 4 10G Ethernet links.

    • 'chan8': Corner-turn engine is bypassed and raw 8-bit data from 8 channelizers is sent directly to the 8 10G Ethernet links.

    • 'shuffle16': Channelize and shuffle within each IceBoard; no inter-board shuffle. For single-board operation or independent boards.

    • 'shuffle128': Shuffle within a crate across 8 boards (128 channels). Data leaves via IceBoard QSFP+; no inter-crate shuffle.

    • 'shuffle256': Shuffle within a crate across 16 boards (256 channels).

    • 'shuffle512': Shuffle between crate pairs (crate N and N+1, N even) to make a 32-board (512-channel) correlator feed.

    • 'corr16': Corner-turn engine is hard-wired to feed 16 channels to the on-FPGA correlator.

    CRS:

    • 'shuffle8': Channelize 8 inputs and send through the UPACK programmable bin packetizer to the 100G CGE offload link.

    • 'corr8': Feed 8 channels to the on-FPGA correlator.

    • 'corr32': Shuffle 4 boards on the same backplane into a 32-input correlator.

    • 'corr64': Shuffle 8 boards on two backplanes (SFP cables between boards) into a 64-input correlator.

    ZCU111:

    • 'corr4': Feed 4 channels to the on-FPGA correlator.

    None or falsy reuses the mode stored by array_init_async().

  • frames_per_packet (int) – Frames combined into one output packet. Limited by FPGA buffering.

  • send_flags (bool) – If True, scaler and frame flags are appended after the data block.

  • chan8_channel_map (list of int) – Channel order for chan8 (and related CT setup). Default is list(range(8)).

  • tx_power (dict) – GTX transmit power levels. None reuses the value stored at array init.

  • integration_period (int) – For corr4 / corr8 / corr16 / corr32 / corr64 only: correlator integration length in frames. Falsy skips starting the correlator.

  • autocorr_only (bool) – For correlator modes: if True, only autocorrelation products are sent.

  • corner_turn_bad_links (list of tuples) – CT outputs [(crate, slot, links), ...] that should preferably not be assigned frequency bins.

  • corner_turn_bin_priority (list of int) – Frequency bins in assignment order (most desirable first). Lowest-priority bins are steered toward bad links when the CT engine allows it.

  • corner_turn_remap_level (int) – How aggressively bins are remapped: 0 = none, 1 = 3rd crossbar only, 2 = crossbars 2 and 3, 3 = all crossbars.

Returns:

None

async set_sync_method_async(method='irig-b', source=None, master=None, master_source=None, master_output=0)

Set the global syncing method and configure every board for it.

The boards start their sync process on the next rising edge of the 10 MHz reference after the trigger event. That event should occur between two reference-clock edges so every board latches the same edge.

Call this before sync_async(). For 'bp_gpio_int' as source, a master board is required (GPIO_INT is enabled as an output only on that board).

Parameters:

  • method (str) –

    Synchronization method:

    • 'irig-b' (aliases 'irigb', 'distributed_time'): Every board syncs when the target IRIG-B time is reached. source is the IRIG-B decoder input (see motherboard set_irigb_source_async). Default source is 'bp_time'.

    • 'trig' (alias 'centralized_soft_trigger'): Every board syncs on the rising edge of source (a REFCLK sync source; see set_sync_source). Default source is 'bp_time'. The master board’s generate_sync() is used later by sync_async().

    • 'local' (alias 'local_soft_trigger'): Each board generates its own software SYNC when sync_async() is called. This resets each pipeline but does not align boards or support multi-board corner-turn modes.

  • source (str) – Sync-signal source. For IRIG-B, an IRIG-B source name; for trig, a REFCLK source name. Ignored for local.

  • master (Motherboard, str, int, or None) –

    Board that generates the time or trigger signal:

    • None: no master is set up.

    • Motherboard object: use that board.

    • str: board with that serial number (include leading zeros).

    • int: board in that slot (1-based).

  • master_source (str) – Source routed to the master’s user output (set_user_output_source on the master).

  • master_output (int) – User output index on the master that carries the sync signal. Default 0.

Returns:

None

async sync_async(delay=0, check=True, align_to_seconds=True, max_trials=3, max_sync_time_difference=None)

Generate a SYNC event across the whole array.

Uses the method configured by set_sync_method_async(). On success, scaler overflow flags are cleared on every board.

IRIG-B path: after FPGA programming the decoder can take ~1 s to see a full second. This method refuses to arm if any board has no valid IRIG. A dummy arm far in the future (IRIG_SYNC_DUMMY_ARM_DELAY_S) measures real array arm time (RPC, switch, load); slack is max(2 * t_arm, IRIG_SYNC_MIN_SLACK_S). With align_to_seconds, the trigger base is the next integer second at least that slack in the future, then IRIG_SYNC_PIPELINE_OFFSET_S plus delay are applied so ADC frames start on that second.

Parameters:

  • delay (float or list) – Extra seconds added after the chosen trigger base. With align_to_seconds this is applied after the next safe integer second (and after IRIG_SYNC_PIPELINE_OFFSET_S). A list is a per-board offset. Default 0: do not skip extra seconds.

  • check (bool) – If True, read SYNC counters on every board to confirm each counter advanced by 1. Automatically disabled (with a warning) if any board’s firmware lacks REFCLK sync logic.

  • align_to_seconds (bool) – If True (IRIG-B only), align the trigger base to the next safe integer second as described above. If False, arm slack seconds after the current IRIG time with no pipeline offset.

  • max_trials (int) – Times to retry the whole SYNC on failure. Default 3. The last exception is re-raised after the final trial.

  • max_sync_time_difference (float or None) – For IRIG-B, maximum allowed Frame-0 time spread in nanoseconds. None uses the value stored by array_init_async() (default 100 ns).

Returns:

None
