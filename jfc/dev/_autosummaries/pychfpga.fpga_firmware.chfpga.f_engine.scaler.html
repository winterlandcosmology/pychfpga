get_gain_table(bank=0, use_cache=False)

Gets the scaler’s complex gain table for the specified bank.

Converts the FPGA table to a numpy array. Linear (mantissa) values are returned; the left-shift must be read separately except in floating-gain mode (see below).

Parameters:

  • bank (int) – Bank number for which the gain is requested.

  • use_cache (bool) – If True, return the cached table when present without reading the FPGA. If False, always read the FPGA.

Returns:

numpy.ndarray – One gain per bin, in natural frequency order (self.fpga.NUMBER_OF_FREQUENCY_BINS values).

If self.USE_COMPLEX_GAINS is True, complex 16-bit integer Re/Im. The log gain is not included; read it with get_shift_left(bank).

If complex gains are off and float gains are off, 16-bit integers. The log gain is not included; read it with get_shift_left(bank).

If complex gains are off and float gains are on, floating-point values that include both the per-bin log gain and the common log gain from get_shift_left(bank).

set_gain_table(gain_list, bank=0, gain_timestamp=None, log_gain=None)

Sets the scaler’s digital gain table for the specified bank.

Gains are provided in natural bin order (increasing frequency order). This method reorders the gains internally to match the native FFT bin order.

If USE_COMPLEX_GAINS is True, the gain_list is interpreted as a 16+16 bit complex number, with log_gain stored in that bank’s left-shift register if not None. If USE_COMPLEX_GAINS is False and log_gain >=0, the gain_list is interpreted as a 16-bit integer real gain and the log_gain is stored in that bank’s left-shift register. If USE_COMPLEX_GAINS is False and log_gain < 0 or log_gain is None, the gain_list is interpreted as a floating point real gain and a common log gain is computed automatically and stored in that bank’s left-shift register.

Parameters:

  • gain_list –

    gains to set. Those are in natural bin order.

    • if gain_list is an NBIN-element list or ndarray, the numeric gains therein are applied to each bin.

    • if gains_list is a scalar int, float or complex numbers, all bins are set to that scalar value.

    • if gain_list is None, no gains are set.

  • bank (int) – The bank in which the gains and left-shift are written (0 or 1). Sets READ_COEFF_BANK to this bank (the target bank, which becomes active on the next frame TLAST if synchronized switching is off).

  • gain_timestamp – unix timestamp when the gains were calculated. If not provided, defaults to current time.

  • log_gain (int) – binary left shift to apply after the linear gain has been applied. Stored in this bank’s left-shift register via set_shift_left. The datapath uses it when this bank is active. See above for when log_gain is interpreted.

Returns:

actual_gains (np.array) – the gains that were actually set, after quantization and normalization, in natural bin order.

Complex and integer real gains do not include the log gain and should match ‘gain_list’ exactly after expansion to NBIN elements unless the provided gains wer enot integers.

However, floating point gains do include the automatically computed common log gain. The actual will roughly match the provided gains, plus or minus the quantization effects if the mantissa has more than 11 bits of precision.

write(addr, data, *args, **kwargs)

Writes an array of bytes to the FPGA memory-mapped address space. Address addr is relative to the base address of the current MMI module.

The MSBs of addr determines the page in which data is written (control, status, RAM etc.). use write_control(...), write_ram(...) etc. to write to specific pages.

Returns the number of bytes written.

write_DRP(addr, data)

Writes a 16-bit value data to a register of a DRP (Dynamic Reconfigurable Port) of the FPGA internal devices (PLL, SYSMON, MGT etc).

Parameters:

  • addr (int) – Address of the 16-bit DRP register word (the address is internally multiplied by 2 to convert it to a byte address)

  • data (int) – 16-bit value to be written

Notes

  • The DRP and RAM pages use the same address space. Either one or the other is connected to the module.

  • The DRP values are stored as little endians
