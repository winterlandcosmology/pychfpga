async pychfpga.hardware.crs.crs_discovery.set_platform_firmware(boards=None, required_version=None, firmware_pathname=None, upload_method='wget', verify_md5=False, **kwargs)

Load tcpipe firmware on U-Boot CRS boards in parallel.

Boards must already have a hostname (from discovery) and are assumed to be in U-Boot. The uploader listens on UDP port 9875 for each board’s FWREQ broadcast and learns the ephemeral reply port before sending FWRESP.

Parameters:

  • boards (list) – Boards to load the platform firmware on.

  • required_version (str) – Required version of the platform firmware.

  • firmware_pathname (str) – Path to the platform firmware ELF file.

  • upload_method (str) – 'wget', 'xmodem', 'xmodem_pipe', or 'loads'.

  • verify_md5 (bool) – Ignored for netconsole binary uploads (MD5 is always checked).

  • **kwargs – Additional keyword arguments (ignored).

Returns:

None

pychfpga.hardware.crs.crs_discovery.tcpipe_version_from_elf(pathname)

Return the GIT_VERSION compiled into a TCPipe ELF, or None.

The firmware stores TCPIPE_GIT=<git describe> as a NUL-terminated rodata string. Discovery beacons advertise the same value as Bootloader Version, so the uploader can skip boards that already match the ELF being loaded.

async upload_and_boot_via_wget(url, elf_path, verify_md5=False)

Send FWRESP/1, download ELF via wget over netconsole, verify MD5, and boot.

Modern U-Boot no longer accepts shell commands in the FWRESP body, so wget is executed on the netconsole session after FWRESP/1 establishes the link.

Waits for the spontaneous U-Boot prompt after wget (progress and Bytes transferred are visible on netconsole). md5sum then verifies the loaded image. After bootelf, silence means U-Boot handed off; the uploader still waits for a TCPIPE beacon before opening TCP.
